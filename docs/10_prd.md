# PRD (Product Requirements Document)

## 概要

ソフトウェアアーキテクチャメトリクスを計算し可視化するツール。

CLIで実行でき、指定された対象ディレクトリに格納されているソースコードの内部品質を計算できる。継続的に実行し計算結果を時系列で見ることでソフトウェア開発者がリファクタリングによってどれくらい改善しているのかを把握できる。


## メトリクス

計算できるメトリクスについて以下に記述する

### 依存グラフ

コンポーネントから他のコンポーネントへの依存関係をグラフ構造で表したもの。

例えば、Kotlinであればコンポーネントとはソースファイル（.ktファイル）のことを指す。


### ACD

ACDとは、平均コンポーネント依存値（Average Component Dependency）のこと。オライリーから出版されている「ソフトウェアアーキテクチャメトリクス」やピアソンから出版されている「大規模C++ソフトウェアデザイン」で紹介されている。

コンポーネントから他のコンポーネントへの依存数を求める。依存数というのは、依存グラフにおいて到達可能なノード数のことを指す。自分自身のみに依存している場合を `1` とする。

依存グラフ内の全コンポーネントの依存数を足した結果が、累積コンポーネント依存値（Cumulative Component Dependency : CCD）である。

CCDをコンポーネント数で割ると、ACDを求めることができる。

### ファンイン・ファンアウト

依存数とは逆に、依存されているコンポーネント数を被依存数と言う（Kotlinならimportされている数）。

コンポーネントの数を限定して考える。例えば、パッケージa,b,cに属するソースファイルだけを考える。ここで、とあるソースファイルの依存数を（限定した範囲内の）全ソースファイルで割った値を、ファンアウトと呼ぶ。依存数ではなく被依存数にしたものをファンインと呼ぶ。ファンアウトとファンインはソースファイル毎に求められるメトリクスである。

### 伝搬コスト

ファンアウトをコンポーネント数で割ると、平均ファンアウトを求めることができる。同様に平均ファンインも求めることができる。

平均ファンアウトと平均ファンインは同じ値になる。

平均ファンアウト（=平均ファンイン）の値を、伝搬コストと呼ぶ。

ちなみに、ファンアウトの合計値は、ACDと同値になる。そのため、ACDをコンポーネント数で割ることで伝搬コストを求めることも可能となる

伝搬コストから、以下のように考えることができる。依存グラフ内のノード数（=コンポーネント数）を `n` とする。
- システムの規模が小さい場合（`n < 500`）は、伝搬コストの値が高くてもあまり注意の必要はない
- システムの規模が中くらいの場合（`500 <= n < 5000`）は、伝搬コストの値が20%以上なら注意が必要。50%以上の値は、大きな循環グループでの深刻な問題を意味する
- システムが大規模の場合（`5000 <= n`）は、伝搬コストの値が10%でも注意する必要がある
